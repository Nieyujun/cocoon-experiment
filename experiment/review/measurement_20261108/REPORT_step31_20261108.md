## 2. 正规T1常规发言桥接

```python
extract_t1_routine_speech_view(
    world_state, agent_id, *, topic_id=None, max_entries=8, allow_demo=False
) -> dict
```

### 显式源记录约定

当前世界快照须有`world_id`、`timepoint="T1"`、`round=8`、非负整数`logical_seq`（快照截止序）、`is_demo: bool`、唯一Agent列表，以及`routine_speech_history`列表。

每条记录严格字段：

```text
speech_id, event_id, world_id, agent_id, topic_id,
phase, round, logical_seq, event_type, role, status, generated, text, is_demo
```

目标发言要求：曝光阶段`phase="exposure"`，轮次1..8，正整数序号且不超过快照截止；`event_type="routine_speech_generated"`或`"discussion_reply"`、`role="assistant"`、`status="completed"`、`generated=True`。这里assistant角色指受试Agent生成回复的消息角色，不是系统提示。

### 筛选与保护

- 从`runtime.measurement_view`深拷贝提取，不读测量问卷，不从任意messages或系统提示回退猜测来源。
- 同一世界其他Agent/其他显式议题不纳入，并记录排除原因；不存在目标有效发言则拒绝。若未指定topic且目标有多个议题，拒绝歧义。
- 空文、HTML、控制字符、未生成占位、测量字段/私有答案/分组泄露标记、错世界、未知Agent、未来记录、重复speech/event/逻辑序及轮序冲突均拒绝。
- 先核查全部目标候选，再按轮次和逻辑序排列，选择最近`max_entries`条（1..64）。超限仅排除整条并记录speech_id，不截断文字，也不靠限条隐藏错误记录。
- user_view用固定中文标题/编号拼接所选原文；每条所选原文均为连续子串，满足mirror文本长度及引用契约。
- 返回`contract="t1_routine_speech_view_v1"`、`content_origin="subject_routine_speech"`、`natural_routine_speech=True`、`requires_protocol_review=False`，包含speech_ids、rounds、source_event_ids、源条目哈希、user_view及其UTF-8 SHA-256。
- `writes_to_memory=False`，原世界前后hash相同，返回对象独立。仅user_view传给mirror，外层源ID/轮次等留在控制器。

**边界**：`requires_protocol_review=False`仅表示来源通道符合本轮确认的常规发言设计，不表示人审、真实运行或正式资格通过。真实生成声明/源事件真实性仍需上层事件链核验，返回`actual_observation_verified=False`、`formal_eligible=False`。

步骤30的`extract_t1_natural_view`保持原样，仍为`subject_measurement_extracted`测量自报备选，`natural_routine_speech=False`、`requires_protocol_review=True`，没有与新常规通道混淆。

## 3. 控制器私有匿名registry

```python
create_blind_sample_registry(entries, *, registry_seed) -> dict
```

每entry严格包含步骤30已验证的`parsed_measurement`、`gold_bundle`，以及私有`world_id/agent_id/environment/arm/timepoint/block_id`。

- 1..4096个样本；seed为非bool整数`0 <= seed < 2**64`，使用局部`random.Random(seed).shuffle`，不改变全局随机状态。
- `(world, agent, timepoint, topic, questionnaire)`不能重复，同一world的arm/environment/block固定；timepoint须与测量封装一致，演示/非演示不能混批。
- 按确定性打乱后的顺序分配`BLIND_0001`等中性ID；随机排列可能碰巧等于原序，不为“看起来打乱”人为反复重抽。
- 每个匿名包经原`build_blind_evaluation_packet`构造，**只有`public_blind_packets`字段可发送给评估器**，不含条件、时点、概率答案或gold真值表。
- `private_mapping`存匿名ID对应条件、源entry索引、整entry/measurement/客观输出/问卷/gold/盲包指纹；整体另有`private_mapping_sha256`。
- 封装contract为`validated_blind_registry_v1`，还保留私有`source_entries`与排列、公共列表hash及`registry_sha256`，供重新构造核对。

**重要**：registry含私有金标准、测量答案及条件映射，绝不可把整个封装发给Evaluator。seed及输入原序也不发送。此版本是内存结构隔离，不提供磁盘访问控制、加密或身份签名。

## 4. 盲评回填与面板契约

```python
reconcile_blind_evaluations(
    blind_registry, blind_evaluations, measurements_by_id, gold_bundle,
    *, expected_registry_sha256=None
) -> dict
```

- `measurements_by_id`为全部匿名ID到已校验测量封装的映射，必须完整一致。盲评可部分完成，但测量记录本身不能静默缺失。
- `gold_bundle`可为一个共用的已验证私有包，或跨问卷时完整的`blind_id -> validated private gold`字典，不能依题目数量猜测金标准。
- `blind_evaluations`为0..N个已校验盲评结果；拒绝未知ID、重复ID、裸输出、失配hash及跨样本重贴ID。
- 先校验registry自含hash，再从source_entries和seed完整重建，比较排列、映射和匿名包。逐样本核对整测量记录hash和客观输出hash，防止主观文字相同但客观答案被替换；金标准也按精确版本绑定。
- 可选`expected_registry_sha256`由可信控制器外部记录传入，用于拦住整个registry一致性改写。未传时返回`trusted_registry_digest_supplied=False`，只做本地一致性检查，不能声称已有可信外部锚。
- 调用原`score_measurement_record`，分别输出8题锚题和4题迁移分数；缺题不填概率。缺盲评的行仍保留客观分，O/U/coverage为None，status为pending。
- 结果`contract="reconciled_blind_panel_v1"`，面板行顺序固定为registry匿名发送序，不因评审返回顺序改变映射。
- 面板每行包含私有world/agent/environment/arm/timepoint/block、topic/问卷ID、anchor/transfer、主BS/Acc/S和上下界、O/U/coverage、客观完整性与盲评状态及来源hash。
- 汇总区分expected_samples、完成/待完成盲评、完整客观行与完整面板行，所有原样本保留；回填结果不含gold_answers，不回写world。

**统计范围**：这是个体×时点长面板，不是网络聚合或正式效应估计。当前项目没有`analysis.py`，本轮没有新增它；只交付下游可消费的明确面板字段。面板含私有条件，不能回送盲评器。

**防篡改边界**：普通SHA-256可检测字段漂移，但不能阻止有权修改所有源entry、映射、hash和外部记录的人整体伪造。应把创建时registry摘要保存在可信控制器记录中。两个完全相同的样本文字/评分结果在语义上无法靠无签名JSON证明来自哪个真实远程调用；真实响应来源仍需事件审计。
