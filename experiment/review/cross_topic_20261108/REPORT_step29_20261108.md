## 2. 公共API与数据约定

```python
merge_and_verify_human_reviews(
    template_or_path,
    reviewer_1_copy,
    reviewer_2_copy,
    adjudication_copy=None,
    *,
    evidence_build,
    live_semantic_path,
) -> dict

verify_human_review_submission(
    submission,
    *,
    evidence_build,
    live_semantic_path,
) -> dict
```

版本常量：`HUMAN_REVIEW_WORKFLOW_VERSION = "human_review_submission_v1"`。

- 输入可为完整JSON字典或项目目录内的本地JSON路径；不接受URL，路径输入大小不超过8MiB。
- 每次先调用原`build_human_review_checklist`重建权威空白模板，不把任意提交件当权威依据。
- 返回的是完整审核文档的新内存副本，加上重算的`counts`、`item_results`、身份集合及限定状态；函数不写文件、不修改输入对象。
- 非法输入统一抛出`ValueError("human_review:...")`，不把提交者姓名、意见或底层原始异常嵌入错误文本。
- `verify_human_review_submission`接受两列都填写的合并件；要核查独立副本槽位归属，必须走`merge_and_verify_human_reviews`并保留各自原始副本。

### 不可变内容

55项的组别、条目数量与顺序、ID、源描述、原证据正文、引文、来源、hash、检查键名及`source_inputs`等均须与权威模板一致。增加/删除/调换条目、改写证据/AI意见、改变full_108_card_review或其他范围声明都拒绝。

允许改变的部分仅为对应审核槽、裁决槽、已有计数与顶层衍生状态。客户端的计数、通过声明和衍生摘要不被信任，均重算；若携带`workflow_version`或`template_sha256`则必须匹配。

### 审核副本归属

- 第一份只能填写`reviewer_1`；其`reviewer_2`和`adjudication`必须与原空白槽完全一致。
- 第二份只能填写`reviewer_2`；其`reviewer_1`和`adjudication`必须与原空白槽完全一致。
- 第三人副本也使用完整模板结构：可以保留两列全空，或原样保留本次两份副本合成后的两列以供阅读；不得改变原审核意见，也不得把两种形式逐卡混杂。

### 槽位完整性

- `pending`槽允许合法部分填写，check值可为null或严格bool，但不计完成。
- 完成槽要求合法非空ID、带时区的ISO-8601时间（包含秒，可有微秒）、非空notes，以及每个check均为严格`True/False`。整数1/0和null不能冒充已完成check。
- 本版所有完成决定都要求notes，特别是需改/拒绝/过强不能留空。
- `model_issue_reviews`完成决定只允许`supported/overstated/needs_revision/acceptable`；其余四组只允许`approved/needs_revision/rejected`。
- `approved/supported/acceptable`必须所有check均为True。程序不会擅自改变旧模板的检查键名，也不根据“是否措辞过强”等问句自行反转布尔极性；按本轮要求执行全部True的通过门槛。实际填写口径应明确告知审核人，若需改变语义须另行升版。

### 身份独立性

- ID按NFKC规范化、首尾去空白、casefold进行比较，拒绝空ID、控制/不可见字符、机器标识及其简单分隔变体。
- 拒绝含ai、llm、gpt、gemini、mimo、claude、assistant、bot、auto、machine等标识的ID；为避免真实姓名片段误中，可使用一致的非机器编号。
- 不仅同一卡片，两列全局ID集合也必须互斥；待审槽中已经填写的ID也参与独立性检查。
- 第三人集合不得与任一审核列的全局ID集合重叠，严禁在其他条目换角色自裁。
- **ID格式与不同字符串不证明真人身份。** 本轮未接身份认证、电子签名、别名归一登记或外部认证服务，返回`identity_verified=False`。

## 3. 分歧和第三人裁决

- 双槽均完成后，decision不同或任意check值不同即`disagreement_detected=True`；仅notes不同不算结构性分歧。
- 分歧未裁决时条目为`awaiting_adjudication`，不计`completed_items`或`passed_items`。
- 裁决状态只允许`not_started/pending/completed`；未完成裁决不允许预填生效结论、理由或ID。
- `completed`裁决须有独立非机器ID、该组合法decision和非空reason；没有分歧或双槽尚未完成时禁止生效裁决。
- **若check本身有分歧，第三人须增加`adjudication.checks`，完整保留原检查键集合并逐项给出bool裁决。** 若仅decision不同、checks完全一致，可省略并沿用一致值。
- 第三人的通过结论也不能与False check并存。原两份审核意见始终保留，不由第三人裁决覆盖。

## 4. 计数与放行定义

| 字段 | 定义 |
|---|---|
| `completed_human_slots` | 完整合法填写的双审核槽数，0..110；不含裁决槽，不代表身份已认证。 |
| `dual_reviewed_items` | 两槽均已完成的条目数，包含等待裁决者。 |
| `completed_items` | 已一致或已独立裁决的最终解决条目数，0..55；包含通过、需改与拒绝。 |
| `disagreement_items` | 曾由双槽结构检测出分歧的条目数，包含已裁决者。 |
| `awaiting_adjudication_items` | 双槽完成但分歧尚未解决的条目数。 |
| `adjudicated_items` | 合法第三人裁决生效的条目数。 |
| `passed_items / needs_revision_items / rejected_items` | 最终解决结果分类；`overstated`计入需改。 |
| `pending_items` | 双槽未全部完成的条目数。 |
| `human_reviews_completed` | 在55项上完成填写的审核角色列数，0..2；不是独立人员数或身份认证结果。 |
| `content_review_passed` | 前48项全部最终通过。 |
| `release_gates_passed` | 7项release gate全部最终通过。 |
| `all_55_items_resolved / all_55_items_passed` | 区分全部解决与全部通过。 |

精确不变量：`completed_items = passed_items + needs_revision_items + rejected_items`；`completed_items + awaiting_adjudication_items + pending_items = 55`。

本工作流只适用于当前`full_108_card_review=False`轻量模板。即使55项全部合法通过，也只返回`lightweight_review_passed_not_formally_eligible`，`approved_for_experiment=False`、`formal_eligible=False`。放行门槛未通过时另列阻塞，不把内容审核完成当全量实验批准。
