更新日期：2026 年 11 月 20 日。依据：开题报告第 3–7 页、当前代码、已有小规模试验记录，以及仓库版本 `94881c6`。

## 一、先明确：接下来最重要的是什么

页面已经能展示，下一阶段应把主要时间放在实验上。最优先补四件事：

1. 让模拟用户每轮真正接收材料、发言并更新记忆，再开展能读取其他用户回应的群体互动。
2. 用真实模型完成均衡/同质、准确/含错误信息的四组比较。
3. 分开检验补充异见、纠错和反思，再判断完整助手是否比单纯提供同样证据更有效。
4. 由组员核查材料和评分，扩大独立重复，写出有效、无效和不确定的结果。

这里的“真实模型实验”是实际调用模型服务，不代表真人实验。开题中的 Agent 是由模型扮演的模拟用户或分析助手。

建议按下面的顺序推进：

```text
核对当前结果和研究范围
        ↓
检查题目与提示词是否限制了可观察的变化
        ↓
准备并人工核对材料
        ↓
补齐逐轮运行、记忆和分组控制
        ↓
小规模试跑四种环境和六种处理
        ↓
固定规则、核算预算、扩大运行
        ↓
单独验证真实群体互动
        ↓
复核评分、分析结果、完成最终报告
```

材料准备和程序改造可以同时做；正式规模运行要等二者都验收完成。

## 三、先分清两条实验线

这是后续设计中必须先说清楚的一点。

**实验线 A：受控阅读与回应。** 每轮给固定数量、类别和长度的材料，模型产生自己的回应并记住经历；讨论输入来自预先审核的固定内容，不把其他模型刚生成的文本实时传回来。它用于尽量清楚地比较四种信息环境和不同干预。

**实验线 B：真实的模拟群体互动。** 模拟用户会在下一轮读到其他用户本轮生成的发言，再回应、更新记忆。它用于补上开题中的“参与讨论、观点在群体内传播”。此处的“真实”仍指实际模型调用，不指真人。

两条线分开保存和分析。线 B 中，模型可能自行生成错误信息，因此 A/C 组只能叫“准确种子信息条件”，不能保证全部互动内容始终准确。必须另外检查传播过程中实际出现了什么。

只完成线 A，可以报告受控信息输入下的认知变化；要声称完成了开题中的连续群体互动，还需要完成线 B。现有 [原实验方案](../破茧助手全量实验方案_v1.md) 第 6.4 节也区分了这两层。

5. 新配置独立保存，例如 `configs/next_phase_v1.json`，不要直接覆盖记录旧研究设计的 `configs/core.json`。

### 产出

- `baseline.md`：代码版本、当前结果位置、已知问题。

### 完成标准

## 步骤 1：先检查题目和提示词，再决定是否扩大运行

现在直接多跑几遍旧题，可能只会得到更多满分或更多 0.5，无法回答开题问题。

### 1.1 检查现实题的难度

1. 列出三个现实议题中各道题的前测答案、概率、正确率，而不是只看平均值。
2. 用不参与后续正式分析的小规模试跑，检查候选新题的前测分布。
3. 优先选择有明确条件、时间范围、数字关系或证据边界的题；不要把有争议的价值判断当成有唯一答案的事实题。
4. 如果某组题在前测几乎全对，记录这一点。可保留为“模型原有知识很强”的对照，另准备新的材料包。
5. 正式题目确定后，不再按效果好坏删题。调试题与正式评估题分开。

### 1.2 检查虚构题里的概率限制

`closed_world_pilot.py` 的 `CLOSED_WORLD_RULE` 要求：未读到相关数据时，把命题为真的概率填在 0.45–0.55 之间。

这不证明旧结果有错，但它会限制模型表达不确定性的方式。因此，下一轮要单独排查提示词是否影响了高信心错误的观察。

1. 保留旧提示词和旧结果，记为旧版本。
2. 准备一版中性说明：解释概率怎么填写，允许表达不确定，但不规定未知时必须落在哪个窄区间，也不暗示应被误导或必须相信某方。
3. 在相同材料、画像和任务下，配对试跑旧说明与中性说明。推荐先用一个情境、8 个模拟用户；这是诊断性试跑，不是正式效果检验。
4. 分别记录 T0、T1 的概率分布、正确率、高信心错误、拒答，以及发言是否转述错误数字。
5. 记录并解释差异，再决定后续固定哪一版。不能只因为某一版更容易“制造茧房”就选择它。

特别注意：全部回答 0.5 时，真假均衡题集可能按既定判定规则算出 50% 正确率，同时概率误差为 0.25。这不能解释为模型掌握了一半事实。

### 产出与完成标准

保存 `item_diagnostics.csv` 和 `prompt_comparison.md`，列明每题、每版提示词的实际情况。完成标准是题目含义明确、概率规则统一、版本可追溯，而不是必须得到高信心错误。若仍没有该现象，后续可以研究纠错与证据整合，但要如实缩小对“茧房致盲”的解释。

## 步骤 2：补齐材料并由组员独立核对

### 要做什么

1. 为每个候选议题列出事实命题、真假依据、支持/反对/中性的表达角度。
2. 延续原方案的材料目标：每议题准备初始阶段 72 张卡、后续阶段 36 张卡。若材料不足，先缩小试跑范围；不要为了凑数量编造出处。
3. 核查每一类材料是否足够满足配额，控制同一卡的重复次数；把初始阅读、干预、后续阅读所用材料分开登记。
4. 对新版本统一准备 8 道核心事实题、4 道迁移题、6 个证据维度和 2 个异见理解任务。这里沿用原方案的目标，不能用它倒改旧试验。
5. 迁移题考查同一知识在新条件或新表述中的运用，不能只是换个说法重复干预原句。只在预定时点测，避免前测提前泄露任务。
6. 安排两名组员分别检查原文支持、数字、否定词、适用条件、翻译和引用。意见不一致时，第三人核对并写理由。
7. 每张材料卡保存来源、版本、改写方式、审核结果。来自同一原始报道的多个网站转载，按同一来源计算。
8. 真实议题和虚构情境分开标注、分开汇总；虚构情境的“官方记录”仅是情境内设定。

### 三类内容必须分开存放

| 内容 | 可以给谁看 |
|---|---|
| 阅读材料与讨论输入 | 模拟用户 |
| 干预允许使用的固定证据 | 助手；随后按设计投递给模拟用户 |
| 题目真值、评分规则、审核裁定 | 评分程序和审核者 |

运行程序要检查实际传给模型的内容。只建三个文件夹，不等于已经避免答案泄漏。

### 产出与完成标准

保存 `material_manifest.json`、`reviewer_1.csv`、`reviewer_2.csv`、`adjudication.csv`。`manifest` 是材料清单，记录本轮使用哪些文件及其版本。

所有入选材料有明确判断依据；两份审核由实际组员完成。程序生成的空表、自动勾选或模型评价都不能算两人审核。已有 [人工审核程序](../cocoon/human_review.py) 可复用，但其部分模板只覆盖特定证据包，不能代替全套卡片的审核。

## 步骤 3：补齐真正逐轮运行的程序

这是主要开发任务。优先复用现有材料分配、记录和评分程序，新增统一的运行程序，不继续复制多个固定为两名用户的小试验脚本。

### 每一轮按这个顺序运行

1. 读取本轮开始时的用户状态，包括画像、原有记忆和可见历史。
2. 按实验条件分配 6 张材料卡，并准备一个讨论输入位置。该位置放什么，由实验线 A/B 决定。
3. 生成这一轮的真实模型请求，保存实际发送的完整文本及材料编号。
4. 模型返回本轮发言、回应对象和可观察的判断依据。保留原始回答，不把它叫作模型内部真实思维过程。
5. 更新记忆，记录新增、移除和摘要内容。记忆中引用的材料或发言编号必须能够回查。
6. 全部用户结束本轮后，再进入下一轮。线 B 只允许读取他人上一轮或更早的输出，避免同一轮中后运行的人额外看见前人的答案。

### 要补的程序能力

- 统一读取议题、人数、独立重复、环境和干预设置，替代旧脚本中的固定常量。
- 支持保存检查点，即记录程序运行到哪里；中断后继续时不重复收费，也不重复投递。
- 把“材料已安排”“请求已发送”“返回已接受”分开记录。不能在模型尚未调用时就把所有材料记成已实际送达。
- 每轮保存状态；复制干预分支时复制整个群体的画像、关系网、历史、记忆、进度及随机状态，分支之间不能互相读写。
- 一次请求失败时记录失败或按固定次数重试，不以网页里的模拟示例补齐。
- 记忆摘要规则、长度上限、截断规则在各组相同。若增加摘要模型调用，要单独计入费用。
- 测量问卷和评分结果不能写回后续记忆；否则前测会变成额外教学。
- 真实运行入口要校验材料审核、预算和版本状态。当前 `python3 -m cocoon run` 明确拒绝正式运行，不能把改一个布尔值当作完成接入。

### 完成标准

先用本地测试回答验证流程，再用小规模模型试跑验证：能顺着记录完整回放某一用户的“本轮输入 → 回应 → 记忆更新 → 下一轮输入”。改动一个分支的记忆，不影响其他分支。发生失败后，原始请求、失败原因及费用仍可查到。

建议新文件名为 `cocoon/experiment_runner.py` 和 `tests/test_experiment_runner.py`，目前尚未创建。不要在报告里把这个建议文件写成已有模块。

## 步骤 4：完成四种信息环境比较

### 分组规则

| 环境 | 每轮立场配额，相对初始立场 | 每轮含错误信息的材料 |
|---|---|---|
| A：均衡、准确 | 同立场 2 张、异立场 2 张、中性 2 张 | 0 张 |
| B：均衡、含错误信息 | 同立场 2 张、异立场 2 张、中性 2 张 | 2 张，共 6 张 |
| C：同质、准确 | 同立场 4 张、异立场 1 张、中性 1 张 | 0 张 |
| D：同质、含错误信息 | 同立场 4 张、异立场 1 张、中性 1 张 | 2 张，共 6 张 |

“含错误信息”要按材料审核结果定义；一张卡可能混有正确与错误内容，不能把“错误卡数量”等同于全部陈述的错误比例。

### 具体操作

1. 每个议题、每次独立重复先创建一组基础画像与关系网，再复制成 A/B/C/D。
2. 四组使用相同模型设置、轮次、材料长度范围、回应次数和记忆规则。
3. 错误信息不能永远只出现在同一个阵营或固定位置；提前安排各类材料的位置与比例。
4. 运行前测 T0，之后逐轮运行 8 轮，再运行后测 T1。
5. 从实际发送的内容计算曝光分布、异见比例、重复次数、错误比例和上下文长度。
6. 先确认分组确实造成不同的信息接触，再比较认知结果。

### 看什么结果

- A 与 B：在均衡条件下，加入错误信息是否改变判断？
- C 与 D：在同质条件下，加入错误信息是否改变判断？
- A 与 C、B 与 D：相同准确性条件下，信息同质是否产生差异？
- `(D−C)−(B−A)`：同质条件是否放大或减弱错误信息的作用？这里比较的是同一评分的前后变化，而不是直接混比不同起点。

没有差异也要保留。只证明阅读内容更集中，不能直接说模型认知受损。

### 产出与完成标准

保存分组表、T0/T1 结果、实际曝光检查表和四组比较图。四组在同一重复内的起点匹配；曝光配额按实际请求验证，而非只读取配置值。

## 步骤 5：补全六种处理，重点补 I1/I2/I3

开题列出四种处理；原方案另外加入完整助手和相同证据阅读两组。继续使用以下编号，避免与旧记录混淆。

| 编号 | 处理内容 | 必须控制的边界 |
|---|---|---|
| I0 | 保持原环境，等量普通阅读 | 有相同的普通回应机会，不能什么都不做、少读一半 |
| I1 | 补充可靠异见 | 补充另一立场有依据的论据，不额外加入个人偏差诊断 |
| I2 | 提供纠错证据 | 按事前规定的错误目标提供核查依据，不由评分答案临时指定“最优纠错” |
| I3 | 比较和反思 | 基于已经看过的材料提问，不新增事实证据；说明什么证据会使其改变判断 |
| I4 | 完整助手 | 信息整理、标注、盲区、整合和认知镜的输出都要有记录，并说明如何进入最终干预 |
| I5 | 阅读与 I4 相同的证据 | 来源、证据原文及新增事实相同，不加入个体化镜像分析 |

### 具体操作

1. 主比较先固定在 D 环境。不要看完结果后才挑差异最大的环境。
2. 在 T1 结束、干预开始前，保存整个 D 群体状态，再复制为六个分支。
3. 随机安排分支运行顺序和可用的响应随机设置，记录真实分配。模拟平台的随机种子不保证外部模型服务逐字可重现。
4. 每组安排两轮干预、每轮一次回应。沿用原方案，每轮可见内容目标为 600–800 中文字符；长度差异上限暂按 10%，先试跑，再在新方案中固定。
5. I4 和 I5 先取得同一份证据，再分别组织呈现。逐项核对实际投递文本，不能只检查输入证据包相同。
6. 反思对话的第二轮应能参考第一轮回应；其他组也保留对应的回应机会，避免只让助手组多说一次。任何额外调用都记录。
7. 每次镜像反馈只能参考该用户的自然发言和允许看的材料，不能读取评分真值或问卷答案来“精准纠错”。
8. I4 如果只实际执行了短组织提示和反思问题，就按这个具体方法命名；五个模块存在于代码里，不代表完整方法已经被检验。
9. 人工检查证据编号是否真的支持对应句子。现有虚构试验的引用语义仍标为待独立审核，这项要补上。

### 产出与完成标准

保存六组的实际投递文本、回应、材料长度、来源和个性化依据；I4/I5 额外保存逐条证据对照表。

所有分支来自同一 T1 起点；I1/I2/I3 的作用没有混在一起；I4 没有比 I5 多拿一份事实证据。没有满足这些条件的比较，记录为偏离设计，不包装成公平对比。

I1/I2/I3 与 I4 的证据内容可能不同，所以它们主要用于策略比较。要回答某个模块单独贡献多少，需要另做同证据条件下的模块删减实验，作为可选扩展。

## 步骤 6：补齐即时、延迟测量和人工评分

### 固定四个时点

| 时点 | 什么时候测 | 用途 |
|---|---|---|
| T0 | 阅读前 | 确认起点 |
| T1 | 八轮阅读后、干预前 | 观察信息环境的影响 |
| T2 | 两轮干预结束后 | 观察即时改善 |
| T3 | 停止助手干预，再读四轮后 | 观察后续信息压力下能否保持 |

T3 的四轮阅读要按轮产生回应和记忆更新，不能再次只累积材料。这里的延迟是模拟轮次，不是现实中过了几天。

### 每项指标实际怎么用

| 指标 | 平实解释 | 本轮注意事项 |
|---|---|---|
| Acc，正确率 | 核心事实题答对多少 | 延续事前固定的 0.5 判定规则；迁移题另算 |
| BS，Brier 误差 | 命题概率与真值的平方差平均值，越小越好 | 作为延迟干预的主要结果；不把准确率不变等同于没有校准改善 |
| S，高信心错误率 | 答错且对自己选择的答案有至少 80% 把握，占全部题目多少 | 把握为 `max(q, 1−q)`，q 是“命题为真”的概率；不是只数 q 大于 0.8 |
| O，证据遗漏 | 没有正确识别的重要证据缺口占比 | 先明确哪些缺口在该时点应被识别，分清缺少信息与未意识到缺口 |
| U，异见理解 | 能否准确复述对方观点、理由和适用条件 | 按预定规则逐项评分，不按是否赞同对方评分 |
| Hn，标准化曝光熵 | 看过的信息是否集中在少数类别 | 从实际接收记录计算，只说明信息分布 |
| X，异见曝光率 | 实际读到的内容中，有多少与初始立场不同 | 分母、分类方式预先固定，不随用户改变态度而倒改分类 |
| C，跨群互动率 | 实际互动中有多少跨越初始群体 | 只在线 B 有真实互动时解释；没有互动时记“不适用”，不能填 0 冒充结果 |

### 人工评分安排

1. 先选不进入正式分析的示例回答，让两名组员分别按规则评分，讨论难理解的条目，修订规则后固定。
2. 正式评分时隐藏组别、干预方法和姓名编号，尽量减少先入判断。
3. 核心事实题由程序按固定答案计分，人工核查解析是否正确。
4. 对 O、U 和助手引用做人工复核。小规模试跑建议全量双人核对；扩大后是否抽样，要在运行前写明抽样比例、方法和争议处理方式。
5. 如果只有抽样经过人工复核，报告中写清实际数量，不称全量人工审核。
6. 保留两人的原评分与第三人裁定，不用最终分覆盖分歧记录。

### 完成标准

每个结果可追到题目、回答、评分规则和版本。拒答、解析失败、模型失败不能记为答对或 0 误差；缺失数量与原计划人数一起报告。测量完成后，后续记忆仍不含问卷答案和评分反馈。

## 步骤 7：先做一次小规模完整试跑

这一步用于找程序和设计问题，不用于宣布助手有效。

### 建议规模

一个合格议题、一个独立重复、每个网络 8 个模拟用户。先跑 A/B/C/D 的 T0–T1，再把 D 分为六组完成两轮干预及四轮后续阅读。

“独立重复”指重新生成一套画像、关系网和材料安排，并完整运行；不能只把同一份回答复制成多个文件。当前分配程序要求人数至少为 8 且能被 4 整除，因此不要直接把人数改成 2 或 3 来调用完整网络程序。

### 依次检查

1. 先跑本地测试回答，确认无答案泄漏、分组串线和重复记账。
2. 再以明确的小额费用上限运行模型；预算不足时停止并保存进度。
3. 抽查一名用户的所有轮次，确认输入、发言和记忆互相对应。
4. 核对四组的实际曝光配额。
5. 核对六组的输入长度、回应次数及 I4/I5 证据一致性。
6. 核对四个测量时点与评分是否齐全。
7. 汇总调用次数、输入输出量、失败、重试和费用；把耗费大的步骤单列。
8. 修复问题后另开版本再试。试跑结果不自动并入之后的正式分析。

### 停止并修复的条件

- 不同组读到了不该读的回答、真值或评分。
- I4/I5 实际新增证据不同。
- 运行失败后偷偷使用模拟数据。
- 原始记录不能重建评分，或费用记录出现无法解释的差额。
- 样本失败率已使配对比较无法成立。

前测满分、没有高信心错误、助手没有优势，属于研究结果或题目适用性问题，不等同于程序故障。不能通过删除这些样本让试跑“通过”。

## 步骤 8：确认规模与费用，再扩大运行

### 两种规模选项

| 选项 | 议题数 × 独立重复 × 每网络人数 | 适用情况 |
|---|---|---|
| 原方案核心目标 | 3 × 6 × 16 | 时间、材料和预算允许时，优先保留原方案规模 |
| 缩小版课程实验建议 | 3 × 3 × 8 | 资源有限时的新方案；必须报告规模缩减，以描述性结论为主 |

两个选项都不是经过当前数据证明“足够”的样本量。先根据试跑的波动和成本决定；若要作强统计结论，还需要论证独立重复数量是否足以支持计划比较。多增加同一网络中的用户，不能完全代替增加独立网络重复。

### 如何估算基础调用量

在实验线 A 中，假设每轮每个用户只调用一次模型，把发言和记忆更新合在该次结果中；四组都测 T0/T1，只有 D 继续做六组干预：

```text
基础用户调用数
= 议题数 × 独立重复数 × 每网络人数
  × [4 × (8 轮阅读回应 + 2 次测量)
     + 6 × (2 轮干预回应 + 4 轮后续阅读回应 + 2 次测量)]
= 议题数 × 独立重复数 × 每网络人数 × 88
```

据此，小试跑约 704 次；缩小版约 6,336 次；原方案核心目标约 25,344 次。

这只包括用户侧基础调用，不含助手内部步骤、评分模型、重试、额外摘要、步骤 1 的提示词诊断和实验线 B。不能把它直接当全部费用。

费用用本次选定服务的实际输入/输出单价，以及试跑测得的平均请求量计算。token 是模型计量文本用量的单位，不等于汉字数。历史试验花费和旧配置里的余额都不能直接当下一阶段预算。

### 运行前固定

- 模型与参数、材料与提示词版本。
- 所有议题、独立重复、随机安排和组别。
- 主要结果、次要结果、评分与缺失处理。
- 每批规模、费用上限、停止规则、固定重试次数。
- 哪些结果属于真实议题，哪些属于虚构情境。

按批次运行。批次检查用于发现执行问题，不能按“助手有没有赢”决定是否继续、追加哪些议题或删去哪些重复。

## 步骤 9：单独完成群体互动实验

这一项补开题中尚未实现的社会互动。建议在受控线稳定后开展，避免同时排查太多问题。

### 具体操作

1. 选一个已完成材料审核的议题，先采用 8 人网络进行开发试跑，再增加独立重复。
2. 每名用户每轮在固定讨论位置读取一条允许看到的他人历史发言，随后决定如何回应。
3. 记录发言作者、回应对象、原文、材料引用、所在轮次及下一次实际送达情况。
4. 下一轮才允许看到本轮新产生的回复；同一分支内传播，不跨实验组传播。
5. 对新增发言是否包含错误事实进行独立核查。核查结果供分析用，不自动反馈给用户。
6. 从相同初始条件复制出“固定讨论输入”和“模型生成讨论输入”两种条件，其他设置相同，比较传播轨迹；两种条件都使用新版本运行，不拼接旧试验。
7. 资源有限时，干预可先比较 I0/I4/I5，并将结论限于这三组；I1/I2/I3 的完整策略比较由受控线承担。

### 不要混淆两种互动指标

如果程序强制每人按固定对象回复，跨群互动率主要反映程序安排，不能说它证明用户主动走出了同温层。要研究主动选择，需要给各组相同的候选对象与动作机会，并记录“可选对象”和“实际选择”。这属于额外设计变化，要单独记录。

### 产出与完成标准

保存真实互动关系表和至少一条能回放的传播轨迹：某用户看到什么、说了什么、谁后来收到了它、又怎样回应。这个轨迹只作具体案例，还要同时报告全部运行的汇总，不能只挑最精彩的一条。

## 步骤 10：按独立网络分析，回答研究问题

### 先整理数据

1. 一行记录一个用户、一个时点、一个环境或分支的结果，保留议题和独立重复编号。
2. 列出原计划人数、实际完成数和失败原因。
3. 先把同一网络内的用户汇总，再按同一初始区组做配对比较。配对就是比较从同一起点分出来的两种处理。
4. 不能把一个网络的 16 个用户、每人的 8 道题和 4 个时点当成互相独立的几百个样本。

### 主要分析顺序

| 顺序 | 要回答的问题 | 分析内容 |
|---|---|---|
| 1 | 信息环境真的不同吗 | 实际材料分布、Hn、X、错误比例、重复次数 |
| 2 | 阅读后判断发生了什么变化 | A/B/C/D 从 T0 到 T1 的网络均值变化 |
| 3 | 完整助手比普通阅读好吗 | D 环境中，I4 与 I0 的 T3 概率误差比较，匹配 T1 起点 |
| 4 | 优势是否超出多给证据 | D 环境中，I4 与 I5 的同一主要结果比较 |
| 5 | 哪种策略在哪些方面有变化 | I1/I2/I3 等组的 S、O、U、正确率，以及 T2/T3 差异 |
| 6 | 群体互动改变了什么 | 实验线 B 的新增内容、实际传播和相应认知结果 |

沿用原方案，主要结果固定为 T3 的 BS，两项主要比较为 I4–I0 和 I4–I5。其余指标不因为结果好看就改成主要发现。

已有 [分析程序](../cocoon/analysis.py) 支持网络汇总、四环境比较和干预配对。它还支持基于实际随机分配的检验以及 Holm 校正，后者用于控制同时做多个主要比较时的误报风险。应先确认新数据满足它要求的记录格式和分配条件，不能伪造分配表来得到检验数值。

报告每组结果、改善幅度和不确定范围。区组少或条件不满足时，只做描述性分析，不勉强给“显著有效”的结论。

### 结果解释参考

- I4 优于 I0，但与 I5 相近：证据可能是主要改善来源，尚未看到组织与反思的额外优势。
- T2 改善、T3 消失：短期变化未能在后续信息压力下保持。
- 正确率不变、BS 下降：答案未变，但概率判断更贴近真值。
- S 一直很低：不能据此证明助手降低了高信心错误，需要说明此前是否本来就没有该问题。
- O 或 U 与正确率方向不同：分别报告，不能合成一个没有事先定义的“总效果分”。
- 只有虚构情境出现变化：结论限于该类情境，不推广成现实公众的认知改善。

## 步骤 11：助手产品只补与实验交付有关的功能

不再把重做界面作为主要任务。优先补下面几项，已有功能先核实，缺的再开发。

| 优先级 | 要补的内容 | 完成标准 |
|---|---|---|
| 高 | 体验页与实验运行清楚区分 | 内置示例不能被误当实验结果，实验运行从受控程序发起 |
| 高 | 调用失败和示例回退明确显示 | 原版网页部分失败会转模拟内容；用户能看清实际使用了哪种内容，实验模式禁止这种回退 |
| 高 | 证据能回查 | 实验报告里的证据编号能打开本次固定证据片段，不只是模型生成的网站名 |
| 高 | 导出本次结果 | 能导出本轮输入、处理方法、结果、版本和状态；不得包含服务密钥 |
| 高 | 认知镜与原话对应 | 展示引用的用户原话、对应证据和反思问题，不凭空诊断用户 |
| 中 | 保存运行进度与恢复 | 页面刷新或请求中断后，可以回查已经完成的任务 |
| 低 | 开放互联网搜索、更多主题与新动画 | 有余力再做；不替代四组实验、分项干预和人工复核 |

产品自检中的风险分、自动生成的立场占比，不直接作为研究的 S/O/U 等结果指标。

- [ ] 一份最终报告、一份简洁汇报稿，图表能对应原始记录。

完成开题应按实际完成内容判断，不按“助手效果是否符合预期”判断。若某项受预算或材料限制未完成，在最终报告中说明范围、原因和已有证据。

## 四、建议的两到三周安排

以下是相对工作日，不是已确认的截止日期。模型排队、材料审核或失败重跑可能延长工期。

| 时间 | 工作重点 | 本阶段应交出的东西 |
|---|---|---|
| 第 1–2 天 | 保存基线、确认范围、检查旧题与概率提示词 | 范围表、问题清单、题目与提示词诊断 |
| 第 3–5 天 | 准备材料并双人审核；并行补逐轮运行程序 | 材料版本、审核记录、可回放的轮次测试 |
| 第 6–7 天 | 一个议题完整试跑四环境与六组处理 | 试跑结果、问题修复记录、实际费用估算 |
| 第 8 天 | 固定新版方案、规模、预算和停止规则 | 可执行配置、运行清单、分析计划 |
| 第 9–12 天 | 按批次运行受控线，推进群体互动验证 | 真实运行、四时点测量、互动记录 |
| 第 13–15 天 | 人工复核、分析、结果图、最终报告与演示 | 完整交付包及与开题的逐条对照 |

如果只剩一周，优先完成一个合格情境的受控全流程、必要的人工复核，以及至少一次真实互动演示；把它明确报告为缩小版研究。不要用增加页面内容代替缺失实验，也不要声称完成了原定多议题大规模检验。

## 五、五人小组如何分工

开题列了五名组员，下面按角色建议分工，具体人选由组内确定。

| 角色 | 主要负责 | 需要另一人复核的部分 |
|---|---|---|
| 运行负责人 | 逐轮运行、分支、记忆、失败恢复、预算 | 输入隔离、配额和费用 |
| 材料负责人 | 题目、材料来源、版本和第一轮审核 | 原文含义、真值、翻译 |
| 助手负责人 | I1–I5 投递、镜像、证据与长度匹配 | I4/I5 同证据、引用对应 |
| 评分负责人 | 问卷、匿名评分、人工分歧处理 | 评分规则与计算复核 |
| 分析与汇报负责人 | 网络汇总、图表、结论、展示 | 数字回查、结论是否超出数据 |

两名审核者独立填写；不要让一个人写两份审核。每两天一起看一次真实产物，进度用“拿得出什么记录”判断。

## 六、代码从哪里改起

下表是开发定位，不是要求全部重写。已有模块继续复用，新增真实运行层把它们串起来。

| 现有文件 | 可以复用什么 | 需要特别注意什么 |
|---|---|---|
| [scheduling.py](../cocoon/scheduling.py) | 画像、关系网、材料配额、分支分配 | 完整网络人数约束；实际接收记录仍要由运行层保存 |
| [runtime.py](../cocoon/runtime.py) | 事件、状态保存、分支、内容校验 | 复制全群体状态；分支不能共享可变记忆 |
| [live_micro_pilot.py](../cocoon/live_micro_pilot.py) | 真实调用、回答校验、小试验记录 | 不直接把累积材料模式称为逐轮交互；固定小规模设置要参数化 |
| [closed_world_pilot.py](../cocoon/closed_world_pilot.py) | 虚构情境材料和三组试验参考 | 旧概率限制、固定 D 环境和两个用户；新版本单独建，不覆盖旧结果 |
| [assistant.py](../cocoon/assistant.py) | 五步助手的受控适配 | 当前正式研究模式仍有限制；完成验收后再设计明确的真实运行入口 |
| [dosage.py](../cocoon/dosage.py)、[delivery.py](../cocoon/delivery.py)、[extractive_control.py](../cocoon/extractive_control.py) | 投递文本、证据及剂量控制 | 检查实际送达文本，不能只检查证据包 |
| [measurement.py](../cocoon/measurement.py)、[metrics.py](../cocoon/metrics.py) | 测量、评分、匿名回填 | 不让问卷进入记忆；检查指标定义与缺失处理 |
| [human_review.py](../cocoon/human_review.py) | 审核模板和合并验证 | 模板不等于人已审核；现有覆盖范围要核对 |
| [analysis.py](../cocoon/analysis.py) | 网络汇总、四环境和六组比较 | 真实分配条件必须成立；三组互动试验不能直接冒充六组完整输入 |
| [budget.py](../cocoon/budget.py)、[mimo.py](../cocoon/mimo.py) | 费用记录和模型请求 | 新预算单独确认；保留失败、重试和未确定结算的记录 |
| [__main__.py](../cocoon/__main__.py) | 当前命令行入口 | `run` 仍拒绝正式运行，需要开发新入口并加相应检查 |

## 七、现在就能做的检查，以及不能误用的命令

先在项目根目录操作，确认 Python 至少为 3.10。若电脑默认 `python3` 版本更低，要将后面的命令替换为已安装的新版 Python 路径。

```bash
python3 --version
git status --short
python3 -m unittest tests.test_prompts tests.test_configuration -q
python3 -m cocoon plan
```

其中 `plan` 只按当前配置估算调用量，不运行实验。上一轮清理后，前面两组测试共 62 项通过；这不是全仓所有测试都已重跑的意思。

```bash
python3 -m cocoon preflight
```

`preflight` 是已有运行条件检查。它可能返回非零状态，表示仍有未完成项；其中部分说明来自早期配置，必须结合实际小试验记录核对，不能单凭一页状态决定当前成果。

不要把以下做法当作完成新实验：

- 执行网页的示例模式，然后导出它的预设内容。
- 把离线演练的 `is_demo` 改为 false。
- 把 `formal_eligible` 改为 true 来跳过审核。
- 认为现在执行 `python3 -m cocoon run` 就能启动完整四环境六组实验。

完整运行的新命令尚未开发，所以这里没有给出一个假装已经可执行的命令。
